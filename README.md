## 지금 바로 실행

1. ZIP의 `index.html`, `app.js`, `config.js`, `data.json`을 GitHub 저장소 최상단에 올립니다.
2. 저장소의 **Settings → Pages → Deploy from a branch → main / (root)** 로 설정합니다.
3. Pages 주소에 접속하면 별도의 데이터 연결 없이 현재 기록을 검색할 수 있습니다.
4. `index.html`을 PC에서 직접 열면 브라우저의 `file://` 보안 제한 때문에 JSON 로드가 차단될 수 있습니다. GitHub Pages 또는 로컬 HTTP 서버(`python -m http.server 8000`)로 확인하세요.

## 자동 동기화 (두 가지 방법)

**권장: GitHub Actions** — `.github/workflows/sync.yml`이 6시간마다 공개 시트 CSV를 읽어 `data.json`을 갱신합니다. 저장소의 Actions 실행과 `contents: write` 권한이 필요합니다. 공개 CSV가 차단되면 작업이 실패하며 마지막 정상 스냅샷은 유지됩니다. `Actions` 탭에서 수동 실행도 가능합니다.

**대안: Google Apps Script**

1. 구글 시트 편집 권한이 있는 계정으로 Google Apps Script를 열고 `Code.gs`를 붙여넣습니다. 원본 데이터 자체는 변경하지 않습니다.
2. **배포 → 새 배포 → 웹 앱**, 실행: 나, 액세스: 모든 사용자로 배포합니다.
3. 발급된 `/exec` URL을 `config.js`의 `endpoint`에 넣습니다.
4. 이 설정이 완료되면 방문 시 먼저 내장 `data.json`을 보여주고, 웹 앱에서 새 데이터를 받으면 갱신합니다.
5. 실시간 자동 갱신은 **방문/새로고침 시** 최신 데이터 요청을 뜻합니다. 이미 열린 페이지에 새 데이터가 즉시 푸시되지는 않습니다.
6. Google Apps Script 응답 크기·실행시간·할당량과 시트 공개 정책을 검증해야 합니다. 60초 캐시는 작은 페이로드에서만 동작하며, 전체 2,000여 건에서는 캐시를 사용하지 않을 수 있습니다.
7. 원본 시트에 수정 권한이 없으면 시트 소유자의 협조가 필요합니다. 공개 웹 앱 배포 시 데이터가 공개될 수 있습니다.

## 포함 기능

- 한국어/일본어/영어 UI 전환 및 다국어 스테이지 검색
- 10개 원본 분류의 스테이지 탐색
- 스테이지 상세 기록, 유닛 구성, 게시물 링크, 플레이어명, 날짜
- 덱 슬롯 수 내림차순 순위(미기록 11枠 제외)
- 유닛 형태별 사용 횟수, 유닛별 사용 스테이지 연결
- 플레이어별 현재 시트 기록 목록
- 스테이지 즐겨찾기(브라우저 저장)
- 모바일/PC 반응형
- 실제 시트 스냅샷 오프라인 데이터 및 Google Apps Script 실시간 갱신 연결 코드

## 미완성 / 별도 데이터가 필요한 기능

- 기존 `noobechan/Nogachasheet/index.html`의 플레이어 순위 산식을 직접 확인하여 **수록 셀당 1건, 동일인 표기 병합, 불명/Deleted/Noname 제외, 동점 공동 순위 및 한국 플레이어 동점 우선 표시**를 적용했습니다. 이후 기존 저장소의 산식이 바뀌면 새 사이트에도 변경 반영이 필요합니다.
- 진화 형태 통합 통계는 **유닛별 진화 매핑 데이터**가 있어야 정확히 구현할 수 있습니다. 현재는 형태별 결과와 동일하며, `window.UNIT_EVOLUTIONS` 객체를 별도로 제공할 때만 통합됩니다.
- 기본 캐릭터 도감·냥콤보 도감·상세 능력치·프로필 이미지·동일인 닉네임 매핑은 아직 미구현입니다. 검증되지 않은 데이터를 임의로 만들지 않았습니다.
- 한국어/영어 스테이지명은 원본 시트에 값이 있을 때 표시하며, 없으면 일본어 원문으로 대체합니다. 모든 맵 이름의 번역은 아직 없습니다.
- `11枠 / 未出`은 원본 시트의 미기록 표시이므로 **공식 기록으로 취급하지 않습니다**.
- 스냅샷은 수동으로 내보낸 시트 기준입니다. Apps Script 연결 전에는 이후 시트 수정이 자동으로 반영되지 않습니다.

## 데이터 재생성

새 시트 내보내기 파일을 `source.xlsx`로 놓고 `python build_snapshot.py`를 실행하면 `data.json`을 갱신합니다. 파서는 Python 표준 라이브러리만 사용합니다.

## 보안

외부 링크는 `noopener noreferrer`로 열립니다. 사이트에는 계정 로그인이나 서버 저장 기능이 없습니다. 원본 시트와 기존 외부 DB를 수정하지 않습니다.

## GitHub 업로드 및 배포 상태

- GitHub 계정 `noobechan` 연결 및 기존 `Nogachasheet` 순위 규칙 확인 완료.
- 기존 저장소는 변경하지 않았습니다.
- 현재 연결 도구에는 **새 GitHub 저장소 생성 기능과 Pages 설정 기능이 제공되지 않습니다**. GitHub 웹에서 새 공개 저장소(예: `NyankoRecords`)를 먼저 만든 후 이 ZIP의 배포 파일을 업로드해야 합니다.
- 배포 대상: `index.html`, `app.js`, `config.js`, `data.json`, `sync_sheet.py`, `.github/workflows/sync.yml`.
- `Code.gs`와 `build_snapshot.py`는 관리용 선택 파일입니다. `source.xlsx`는 배포할 필요가 없습니다.
- 브라우저 자동 테스트는 실행 환경에 Chromium 바이너리가 없어 미완료이며 JavaScript 문법 검사는 통과했습니다.
